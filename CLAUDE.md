## Architecture rules

- Pages and components never query the database. All data goes through `src/services` (DAL).
- **Every restaurant-scoped service function starts with `await requireRestaurantAccess(restaurantId)`**; admin-only ones with `requireAdmin()` (`src/auth/dal.ts`). New functions must do the same. Access is enforced on the server, never only in the UI.
- Every restaurant-owned table has `restaurant_id`, and every query filters on it.
- Server Actions live next to their route (`actions.ts`) as thin wrappers: coerce inputs to the expected types, call the service.
- Mutations that must stay consistent are single conditional SQL statements or transactions (see `awardStamp`, `redeemReward`).
- Shared UI: `Card`, `Stat`, `Badge`, `Button`/`buttonClass`, `PageHeader`, `Skeleton` in `src/components/ui`. Never override a `Card` padding or border with extra classes (Tailwind conflicts); use a plain element instead.
- Charts are hand-built SVG in `src/components/charts`, following the dataviz skill (single series per chart, table view, tooltips).

## Next.js 16 specifics (read `node_modules/next/dist/docs/` before using an API)

- `cacheComponents` and `partialPrefetching` are on. Request-time data must sit behind `<Suspense>`.
- **Never** call `new Date()`, `Date.now()`, `Math.random()`, `randomUUID()` or open a DB connection before `await connection()` (or `cookies()`) in render paths, or the prerender of the shell fails. Services use the `db()` helper, which awaits `connection()`; session reads compare expiry with SQL `now()`.
- `src/proxy.ts` (formerly middleware) only checks the session cookie's presence and redirects to `/login`.
- A `notFound()` inside a Suspense boundary renders the 404 page with HTTP 200 (known, not fixed).

## Database

- Driver: `@neondatabase/serverless` (WebSocket, **port 443**). The owner's network blocks port 5432, so do not switch to a TCP driver or use `drizzle-kit migrate/push/studio` (they use 5432).
- Schema change: edit `src/db/schema.ts`, run `npm run db:generate` (writes `drizzle/NNNN_*.sql`, commit it), then `npm run db:migrate`.
- `npm run db:seed` **deletes everything** and reloads demo data with new random passwords in `seed-credentials.txt`.
- Dates: stored as `timestamptz`/`date`; "today" is computed in UTC (`getToday()`).

## Verifying a change

1. `npm run lint`
2. `npm run build` (needs no database), then `npx tsc --noEmit` (route types are regenerated by the build, so run tsc after it).
3. Run it: `npx next start -p 3100` and check the pages in a real browser (headless Chrome via the DevTools protocol works; `--virtual-time-budget` hangs). Read the server log for errors, not only the HTTP status.
4. After testing against Neon, `npm run db:seed` to restore clean demo data.
